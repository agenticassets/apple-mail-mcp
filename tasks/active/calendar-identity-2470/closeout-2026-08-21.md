# AGENTIC-2470 calendar identity closeout (2026-08-21)

**Issue:** AGENTIC-2470, "Cannot target duplicate Calendar names by account"

**Branch:** `fix/post-3.11.7-defect-audit`

**State:** Shipped. Merged as PR #94 (`f1264c6`, 2026-08-21) and released in tag `v3.11.8`, which points at that same commit. The Linear issue is the execution record.

## Goal

Make duplicate Calendar.app display names safe by using Calendar.app's stable
`calendarIdentifier` for every scoped calendar read and write.

## Completed locally

- `list_calendars` now exposes the stable identifier and calendar events retain
  the selected `calendar_id`.
- Existing `calendar` and `calendars` inputs accept an opaque identifier, or an
  exact display name only when that name is unique. Duplicate names fail closed
  with candidate identifiers.
- AppleScript and EventKit calendar paths bind the resolved identifier rather
  than a display name. This covers list, get-by-id, availability, create,
  batch create, update, delete, and calendar management.
- Synthetic regressions cover duplicate display names, identifier selection,
  AppleScript script generation, EventKit parity, and caller propagation.
