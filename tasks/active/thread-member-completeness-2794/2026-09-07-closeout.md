## Goal

AGENTIC-2794: a conversation's earlier, attachment-bearing member was silently missing from thread enumeration, attachment listing, and thread export, and every completeness signal reported the partial result as whole. Reproduce it, find the root cause, fix it, verify live, and harden the surrounding surface.

## Decisions made

- **The thread scan ceiling (400) is a deliberate exception to `SEARCH_HARD_CEILING` (50).** Measured live, same anchor, only the bound varied: 50 → 6.8 s / 5 members; 150 → 10.9 s / 9; 400 → no worse than 150. Cost is flat past 150, so the ceiling buys completeness at bounded cost. Rejected: keeping the 50 ceiling for consistency, which would have left the bug in place.
- **The `recent_days` date floor is excluded from `thread_incomplete`.** Implemented the other way first and reverted: the floor fires whenever a mailbox holds anything older than the window, so the flag was true on every realistic call. Split into `window_truncated`. Rejected: a single union flag (honest but ignored in practice) and dropping the date-floor report entirely (useful flag, lost information).
- **`max_messages` truncation is also a caller-chosen bound**, so `return_limit_reached` is reported separately rather than folded into `thread_incomplete`. Same reasoning as the date floor.
- **Marker rows travel on their own prefixes, never as extra record fields.** `_parse_search_records` splits with `split("|||", 14)`, so a 16th field would fold into `was_replied_to`; and left in the stream, a short marker row is silently *dropped* rather than mis-parsed. Hence `split_thread_markers` runs first.
- **No shared marker-parsing primitive was extracted** across the three parsers. The only common step is one line each, and a shared entry point would create the exact risk of a marker row reaching the record parser.
- **The attachment-count probe binds its error variable** rather than using a bare sentinel arm, so it needed no bare-try ratchet allowance. Preferred over bumping the baseline.

## Things deliberately deferred

- `include_sent=False` bounds the export candidates but not the thread scan, so a Sent-resident member can be enumerated and then dropped.
- Text mode reports `FOUND 0` when the anchor was recovered: the banner renders inside AppleScript while anchor retention happens in Python. JSON mode is correct; skills now direct completeness checks to JSON.
- `thread.py`'s ceiling detection reads `count of messages` first, which is a known stale-prone property, rather than slicing optimistically and recovering on error the way `script.py` does. Pre-existing shape, preserved.
